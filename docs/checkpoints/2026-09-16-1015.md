## Decisions

- **Scoped rust#12 to the Rust core only**, rejecting its own stated full-stack scope for
  this task. Verified there is no C ABI in the `rust` repo at all (no `cabi` crate, no
  `extern "C"`, no `#[no_mangle]`) — each binding repo carries its own `crates/cabi`. The
  agent delivers the public envelope API the bindings will later serialize.
- **Hand-roll the envelope's JSON, do not add `serde_json`.** It is a dev-dependency only
  and the crate keeps a deliberately lean runtime tree; the envelope is a fixed nine-field
  object.
- **Did not launch the path-dependency wave (#225–230) in parallel** with the running
  binding migrations, even though asked to. Both waves edit the same Cargo.toml dependency
  line and would collide on merge, and the unpublished library they are meant to consume
  does not exist yet (#224 is still writing it; `rust/` currently equals published 0.7.0
  byte-for-byte). Queued them with `blockedBy` instead.
- **Reported that the `wasmi 2` migration has no target.** Grepped every manifest: `wasmi`,
  `wasmtime` and `wasmer` appear nowhere. The only WASM is `js/crates/wasm` on
  `wasm-bindgen 0.2` + `js-sys 0.3` via `wasm-pack` — compiling Rust *to* WebAssembly,
  which is not what `wasmi` (a WASM interpreter embedded in a host) does.
- **Closed spec#4 after initially leaving it open**, on the reasoning that its remaining
  Definition-of-Done item is work in seven other repositories.
