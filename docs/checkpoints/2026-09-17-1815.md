## Decisions

- **The body separator is `>>>>> lang=`, not `## lang=`.** The operator's
  point: a delimiter must not be syntax the document itself uses. Measured
  before switching — zero lines with three or more `>` in the whole
  corpus, while `##` appears constantly. It also removed a coupling: a
  heading separator would have had to be stripped before the heading
  validator ran.
- **The format names no languages.** It requires a language at most once
  per file and says nothing about order, because the decoded result is a
  map. The en/ru/zh requirement is checked one layer up, against a single
  declared list — not by a first-file-wins rule that would adopt a typo.
- **Cut points are shared, chosen once as paragraph-boundary indices.**
  Per-language proportional cuts are what made the files unreviewable.
  The reference is the longest language, ties broken on LANGS order.
- **The reader stayed dumb.** Making it skip fenced code blocks was tried
  so the README could show a separator, and abandoned: § 4 is wall-to-wall
  grammar fences and the tracker lost a separator immediately. Instead a
  separator is recognised only at column zero, and the README's examples
  are indented by one space with that named as the escape hatch.
- **Translations are corrected, English is not.** English is canonical.
  The acceptance signal is asymmetric on purpose: spec.md must stay
  byte-identical while spec.ru.md and spec.zh.md change.
