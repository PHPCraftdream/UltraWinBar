## Session summary
Сессия началась с диагностики зависаний Tor Browser (не относится к дальнейшей работе), затем перешла к доработке форка UltraWinBar (классическая панель задач для Windows) в `<repository>`, установленного и в системе как `<install-directory>` (net10.0), но собираемого локально под `net6.0-windows` с патчем `rollForward: LatestMajor` в runtimeconfig.json (SDK в системе только 8.0.420). Рабочий процесс деплоя, который нужно соблюдать и дальше: собрать (`dotnet build -p:TargetFrameworks=net6.0-windows`), остановить работающий процесс UltraWinBar по PID, скопировать *.dll/*.exe/*.runtimeconfig.json/*.deps.json/Themes/Languages/Resources из `bin/Debug/net6.0-windows` в системную папку, запустить оттуда — чтобы пользователь никогда не оставался без панели задач.

Реализована крупная фича — поддержка нескольких панелей задач (по одной на каждый край экрана Left/Top/Right/Bottom), с общим механизмом приоритета регистрации в Windows AppBar API (вертикальные по умолчанию первыми, либо явно через пункт меню «Растянуть», который двигает свой edge в начало `Settings.EdgePriority`). Каждое приложение (или, при зажатом Ctrl во время перетаскивания, отдельное окно) может быть закреплено за конкретной панелью и переезжает туда же при следующих запусках (`TaskAssignmentManager`, `Settings.TaskbarAssignments`). Трей, часы, кнопка Пуск и языковой индикатор — каждый живёт ровно на одной панели, настраиваемой независимо (`TrayEdge`, `ClockEdge` — теперь отдельно от трея, `StartButtonEdge`, `LanguageEdge`), плюс `DefaultTaskEdge` — куда попадают ещё не закреплённые приложения (пункт меню «Сделать главной» на панели).

Важный технический тупик и его решение: изначальный drag-and-drop окон между панелями делался через gong-wpf-dragdrop (уже использовавшуюся в проекте библиотеку) — но `Drop` никогда не срабатывал, даже при перетаскивании внутри одной панели. После изучения полного исходника библиотеки (via WebFetch с raw.githubusercontent.com) стало ясно, что `Drop` вызывается безусловно после `DragOver`, значит проблема была в том, что сам WPF `Drop` routed event не долетал — вероятная причина: обычный `Button` (`AppButton` в `TaskButton`) захватывает мышь при нажатии, что конфликтует с OLE drag-циклом. Решение — полностью заменить механизм на собственный ручной drag через уже существовавший в проекте `LowLevelMouseHook` (тот же, что используется для перетаскивания самой панели за угол экрана): отслеживание порога перемещения, явный `ReleaseMouseCapture()` на кнопке при превышении порога, hit-test экранных координат по всем открытым `Taskbar`-окнам через `Application.Current.Windows.OfType<Taskbar>()`. Этот же паттерн затем переиспользован для перетаскивания мышью блоков часов и трея (значков уведомлений) между панелями — они были разделены на два независимых `GroupBox` в `Taskbar.xaml` (были одним общим "Tray" блоком).

Также найден и исправлен смежный баг: языковая панель (`InputLanguage`) была видна одновременно на ВСЕХ панелях сразу из-за race condition — `Host` (biNding через `FindAncestor`) мог быть ещё `null` в момент первого `Loaded`, а fallback-логика `ShouldShow` трактовала `Host == null` как "показывать" на всех. Исправлено через `PropertyChangedCallback` на `HostProperty`, убран null-fallback. Это же объясняло замеченный лог-спам "Error getting locale identifier: culture ('0')..." — несколько экземпляров `InputLanguage` одновременно гоняли свой `DispatcherTimer`.

Отдельно исправлены: кнопка Start сделана icon-only (убран текст и связанный с ним `MinWidth=99`/асимметричный `Margin` в теме Windows XP Blue, т.к. фон кнопки — растягиваемый `ImageBrush`, ломать не должно); меню Пуск теперь открывается через `StartMenuMonitor.ShowStartMenu(Host.Handle)` всегда (раньше — только при двух включённых настройках multi-monitor, которые не про этот сценарий), а `relocateStartMenuByClass` в `StartMenuMonitor.cs` использует `AppBarEdge` конкретной панели, где нажата кнопка, вместо глобального `Settings.Edge`.

Все изменения из коммитов `07bdd46`/`f5609b6` уже в git (ветка master форка UltraWinBar, история апстрима PHPCraftdream/UltraWinBar сохранена). ## Decisions
- Отказались от gong-wpf-dragdrop для переноса задач между панелями в пользу собственного `LowLevelMouseHook`-based drag — потому что `Drop` не срабатывал даже внутри одной панели (вероятная причина — конфликт `Button`-капчи мыши с OLE drag-циклом), а не только в кросс-оконном сценарии, как предполагалось изначально.
- Обычное перетаскивание кнопки задачи переносит **всё приложение**, `Ctrl`+перетаскивание — **только это окно** (пользователь явно попросил поменять местами относительно первой реализации).
- `DefaultTaskEdge` заведён как отдельная настройка, НЕ переиспользующая `Settings.Edge` (физическое расположение "основной" панели) — потому что «Сделать главной» должно управлять только тем, куда падают новые неприкреплённые окна, не двигая саму панель.
- Часы и трей (значки уведомлений) разделены на независимые панели/настройки (`ClockEdge` vs `TrayEdge`) по прямому запросу пользователя, хотя раньше жили в одном `GroupBox`.
- Деплой всегда идёт в системную папку `Programs\UltraWinBar`, а не через запуск debug-сборки напрямую — по явному требованию пользователя "никогда не оставлять без рабочей панели задач".
