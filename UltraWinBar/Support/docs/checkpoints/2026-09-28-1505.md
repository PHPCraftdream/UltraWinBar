## Session summary
The user is hardening UltraWinBar (WPF fork of RetroBar, multi-panel taskbar) and, in this stretch, polishing how the Open Shell Start menu appears. Placement was already fixed (b6cdd35: the menu always ends at (1253,41) beside the panels). This session removed the remaining flashes, all in commit d061fe0 (pushed, CI green):
- StartMenuFade (Core/Windows/StartMenu/StartMenuFade.cs) makes the Open Shell menu transparent via WS_EX_LAYERED + alpha 0 from the moment it takes focus (DWMWA_CLOAK is denied across processes), then fades it in over 150 ms once placed; 2 s timeout shows it where it is; style restored on close/exit.
- StartMenuAvatarGuard (StartMenuAvatarGuard.cs) handles Open Shell's avatar (OpenShell.CUserWindow, per-pixel layered). Moving it with SetWindowPos waits for Explorer's thread, which shows the avatar first, so instead a TIME_CRITICAL hook thread (DesktopActivationHookThread + WinEventHook SHOW/LOCATIONCHANGE filtered to the menu's pid/tid) keeps its alpha 0 via UpdateLayeredWindow(hdcSrc=NULL) until the UI thread calls MarkPlaced; its alpha then follows the menu fade (StartMenuFade onAlpha callback); Disarm makes it opaque. Each of our ULW calls raises one LOCATIONCHANGE echo; an event counts as echo only if the window state (visible+rect) is unchanged since our hide — the earlier count-only rule skipped Open Shell's move+show and caused frame flashes when Open Shell was slow.
- StartMenuMonitor.WarmUp (Placement.cs) runs once at ApplicationIdle after start: PrepareMethod over the Start menu types and a dry run on a hidden own window, because the first Start press after launch ran cold (JIT, P/Invoke stubs) and hid nothing in time.
- WinEventHook got optional process/thread filters; DesktopActivationHookThread got Stop() (no join).
- Rejected on the way: moving the menu early from a hook thread (Explorer processes the cross-thread SetWindowPos only after showing menu+avatar); moving Explorer's hidden taskbar so Open Shell computes the right place itself (too invasive).
The probe (UltraWinBar/Support/tests/StartMenuProbe) prints layered alpha and has --list and --trim PID; it opens Start itself only with --open N [--click 1841,18] — ask the user before running it, they use the PC meanwhile.

## Decisions
- Menu hidden with layered alpha (SLWA) rather than cloaking: cross-process DWMWA_CLOAK returns E_ACCESSDENIED.
- Avatar hidden with UpdateLayeredWindow blend on a hook thread rather than SetLayeredWindowAttributes (would break Open Shell's later ULW calls) or early SetWindowPos (queued behind Explorer's show).
- Echo detection by unchanged window state, not by count alone.
- Warm-up of the placement path at idle after start instead of a permanent background detector thread.
- Checkpoints stay in UltraWinBar/Support/docs/checkpoints, committed with a normal git commit.
