## Decisions

- **Spec 0.7.1 is a PATCH, argued rather than assumed.** § 8.5 adds no
  obligation: § 8.1 already required accepting *every* fixture under `valid/`;
  § 8.5 only makes that "every" checkable. The reasoning is written into the
  changelog so the classification is a position, not a default.
- **§ 8.5 is MUST, not SHOULD, and is bound to the § 8.4 claim.** Advice from an
  `fh` agent, verified against the spec text: SHOULD would make the document
  stricter about the obligation than about the evidence for it, and RFC 2119's
  own test for SHOULD fails because no legitimate reason to ignore it could be
  named. Binding it to the claim dissolves the "runner is a third actor" problem.
- **The two writer rejections are named apart in the envelope** —
  `Unrepresentable` versus `UnrepresentableAt`. User's decision, against my
  recommendation to leave them identical. Done before publication because it
  would be a breaking wire change afterwards.
- **Release order is strict:** spec 0.7.1 -> rust 0.7.1 -> bindings. Publishing
  the crate first would have it claim a spec version that does not exist.
- **Binding floor becomes `ktav = "0.7.1"`**, which in Cargo means
  `>=0.7.1, <0.8.0` — the floor rises, the ceiling stays inside 0.7.x.
- **PHP's six empty-compound fixtures are surfaced as named known gaps**, not
  silently value-compared. The byte-exact assertion re-arms automatically when an
  entry is removed, verified by removing one and watching the suite go red.
